- После оплаты VPS контейнеры API/PostgreSQL/Redis запустились. Проверенные production-логи содержат Workers AI `AI_LIVE`, HTTP 200; отключения AI на момент диагностики нет. Модель и короткие промпты не меняются.
- Вкладки используют общий кешированный импорт для прогрева и отображения. Текущий экран остаётся до загрузки следующего; синхронное наложение анимаций без пустой фазы `exit → wait → enter`. Ошибка импорта предлагает повтор, быстрые переходы учитывают последний выбор. Прогрев не монтирует скрытые страницы.
- Инициализация `/today` принадлежит оболочке, а не каждому монтированию Дома. Параллельные запросы объединяются; успешный пакет переиспользуется в пределах текущего дня/профиля. Возврат после 5 минут и fallback-таймер сохраняют обновление. Ротация JWT того же пользователя не отбрасывает ответ; ответы прежнего аккаунта/настроения игнорируются.
- Пул поддержки: один refill на персональный `short-v2`-ключ; локальный single-flight + Redis lock с владельцем на 50 секунд. AI SDK: timeout 20 секунд, без скрытых SDK retries; сервис сохраняет один повтор. Ожидание пустого пула в HTTP ограничено 8 секундами, единственный refill может завершиться в фоне. Ошибочный batch кешируется отдельно на 300 секунд, временная поддержка не пишется в PostgreSQL. Основные TTL 36/24 часа сохранены.
- Окно праздников имеет стабильную высоту, внутреннюю прокрутку и направленные переходы без масштабирования. Возврат восстанавливает позицию списка; выбор сбрасывается после закрытия. Повторный выбор текущего тона не запускает загрузку; во время смены тона нельзя сохранить/отправить предыдущую открытку.
- Web Share: файл готовится заранее (таймаут 8 секунд), по клику отправляется готовый файл либо публичная ссылка. Отмена не открывает второе окно. Подтверждение копирования появляется только после успешного clipboard API; MAX — копирование для ручной вставки.

Матрица: 320×640, 360×640, 390×844, 412×915, 640×360, 844×390. Это не проверка физического Safari/Yandex Android.

## 1. Что это за проект

**YoYoJoy Day** — PWA-компаньон к бумажному ежедневнику YoYoJoy. Пользователь сканирует QR-код в бумажном календаре, регистрируется и каждый день получает персонализированный контент:

- **Гороскоп** — по знаку зодиака, короткая/подробная версия.
- **Фраза поддержки** — подстраивается под текущее настроение (6 вариантов: Спокойна, Нормально, Устала, Тревожна, Грустна, + смена).
- **Праздники дня** — календарные (открытки с 3 тонами — милая/с юмором/циничная) и персональные «дни заботы о себе» (привязаны к целям пользователя).
- **Цели** — до 4 штук, с прогресс-баром и вехами (5/10/15/20 дней).
- **Push-уведомления** — по расписанию, которое настраивает сам пользователь (время для каждой категории отдельно).

**Дизайн-система** — Zen-Emerald: `#006a65` (primary), `#2FA7A0` (accent), `#fcf9f4` (фон). Mobile-first, с отдельной горизонтальной (landscape) адаптацией **только** через Tailwind-модификатор `landscape:` — никаких `md:`/`lg:` брейкпоинтов (десктоп/планшет просто центрируют мобильный интерфейс).

**User flow:** QR → Welcome → Регистрация (email) → OTP-код и отдельное письмо с двумя PDF → Push-разрешение → Настройка профиля (дата рождения → знак зодиака автоматом, пол, имя) → Home.

## 4. Критичные правила (не нарушать)

1. **AI строго на бэкенде** — ключи только в `backend/.env`/`.env.prod`, фронт про AI ничего не знает.
2. **Landscape только через `landscape:`** — ни `md:`, ни `lg:`, ни кастомные media-query (кроме одного legacy-исключения в `RegistrationPage.tsx`, которое не копировать).
3. **Partial mood update** — при смене настроения пересобирается **только** блок поддержки, гороскоп и праздники не трогаются (экономия LLM-токенов).
4. **Immutable bookmarks** — закладка сохраняется как JSONB-снапшот на момент нажатия, изменение данных в БД не меняет текст в уже сохранённой закладке.
5. **Dumb client push** — фронт только получает Web Push (VAPID) подписку. Перед `PushManager.subscribe()` авторизованный клиент запрашивает публичный VAPID-ключ у `GET /api/push/public-key`; он не вшивается в Vite-сборку и не берётся из `VITE_WEB_PUSH_PUBLIC_KEY`. Сервер читает `WEB_PUSH_PUBLIC_KEY`, `WEB_PUSH_PRIVATE_KEY` и опциональный `WEB_PUSH_SUBJECT` только из окружения. Расписание и логика триггеров — целиком на сервере (NestJS `@Cron`). Каждая категория отправляется отдельно; календарные праздники не объединяются, персональная забота отправляется по каждой активной невыполненной цели, а веха — отдельно с названием цели. UI-fallback `calm` при отсутствии целей для push не применяется. В Settings блок восстановления показывается только при проблеме на **текущем устройстве**; подключение подтверждается ответом `POST /api/push/subscribe` с `{ subscribed: true }`. Тестовой push-отправки и `POST /api/push/test` больше нет. На iOS запрос разрешения остаётся только внутри явного пользовательского нажатия.
6. **AI fallback обязателен, но никогда не постоянен** — при падении API или отсутствии ключа бэкенд отдаёт содержательный локальный текст, кладёт его только в Redis на 300 секунд и возвращает `meta.contentSource=fallback`. Fallback нельзя записывать в `horoscopes`, `support_phrases` или `daily_feed`; фронт тихо повторяет `/api/today` после TTL. Живой ответ кэшируется на 36 часов.
7. **Даты AI-контента только ISO** — ключи Redis, `horoscopes` и `daily_feed` используют `YYYY-MM-DD` в timezone пользователя. `DD.MM` остаётся только для календарных праздников и отображения в UI.
8. **Секреты никогда не коммитить** — Workers AI token хранится только в production `.env`; перед каждым коммитом проверять diff.
9. **Auto-commit, но НЕ auto-push** — после завершённой и проверенной задачи коммитить без вопроса. **Форс-пуш и любые деструктивные git-операции — только с явного разрешения**.

## 5. Ключевые баги, найденные и исправленные (чтобы не наступать повторно)

Это не журнал изменений — это список неочевидных вещей, которые реально стоили времени и могут повториться.

- **OpenAI с московского VPS не работает.** Прямой OpenAI API и старый Cloudflare Worker возвращают `403 unsupported_country_region_territory`. Нельзя пытаться «чинить» это возвратом Gateway/прокси: текущий провайдер — Cloudflare Workers AI REST API. Проверка production: безопасные логи `AI_LIVE model=... status=... durationMs=...`; токен, промпт и имя пользователя не логируются.
- **Короткий/сломанный AI JSON.** JSON mode не гарантирует соблюдение схемы, поэтому сервер проверяет поля через Zod. Актуальный короткий контракт: «Главное» 2–4 предложения/160–500 символов, «Подробнее» 3–4/350–850, поддержка 1–2/60–220; совет 1–2, Луна и аспект по одному. Лимиты `max_completion_tokens`: 1400/400/1200 для pack/single support/batch. Для `gpt-oss-120b` обязателен `reasoning_effort: low`: без него модель может потратить весь лимит на reasoning и вернуть пустой `content`. Невалидный ответ повторяется ровно один раз; `408/429/5xx` — после 750 мс, `401/403` — без повтора.
- **Поле имени исчезало после первой буквы.** `ProfileSetupPage` переключал `<input>` на `<p>` по текущему `userName`, а `setUserName` пытался делать PATCH на каждый символ. Теперь решение «имя было при входе на экран» фиксируется один раз, новое имя хранится в локальном draft и отправляется единственным `PATCH /api/profile` вместе с остальным профилем после «Продолжить».
- **Двойная конвертация времени пушей.** Фронт конвертировал введённое время в UTC (`localTimeToUtc`), а бэкенд **уже сам** переводит `HH:mm` в локальное время пользователя через `prefs.timezone` — получался сдвиг на разницу часовых поясов, и пуши либо не приходили, либо приходили не в то время. Файл `src/lib/time.ts` с этими конверсиями был полностью удалён как мёртвый/вредный код — время хранится и передаётся как есть, без UTC-прослойки.
- **`rounded-xl` в этом проекте = 48px, не 12px.** `tailwind.config.js` переопределяет всю шкалу скруглений под «мягкий» Zen-Emerald стиль: `DEFAULT=16px, lg=32px, xl=48px, full=9999px`. На больших карточках (350px+) это ок и выглядит красиво. Но на **любом маленьком элементе** (мини-карточка, бейдж, миниатюра высотой ~100px и меньше) 48px радиус реально обрезает контент, который стоит ближе к углу, чем сам радиус — это баг, который выглядит как «текст обрезается», а не как проблема со скруглением, и совершенно не воспроизводится в девтулс-эмуляции без явного расчёта геометрии угла. Если где-то на мини-элементе видно необъяснимое обрезание текста/иконки у края — **первым делом проверять computed `border-radius` этого конкретного контейнера**, а не гадать про переносы строк или шрифты. Безопасные для мелких элементов классы в этом проекте: `rounded-sm` (2px) и `rounded-md` (6px) — они НЕ переопределены конфигом.
- **`mx-auto` на элементе CSS Grid отключает stretch.** Если grid-item имеет `mx-auto`, его ширина считается по контенту (shrink-to-fit), а не растягивается на всю колонку — это один раз реально схлопнуло горизонтальную карусель настроения до 68px. Если элемент внутри `landscape:grid`/`grid-cols-2` и должен занимать всю колонку — добавлять `landscape:mx-0 landscape:w-full` (или просто не использовать `mx-auto` внутри grid-контекста).
- **JSX-комментарий `{/* ... */}` нельзя ставить прямо перед корневым элементом внутри `return (...)`** — Babel падает с `Unexpected token`. В таких местах — обычный `//`-комментарий строкой выше `return`, а не JSX-комментарий внутри него.
- **Subscribe-churn в Web Push.** `subscribeToPush()` раньше всегда делал unsubscribe+resubscribe, что на iOS Safari плодило новый `endpoint` при каждом заходе и оставляло мёртвые записи в БД. Исправлено — сначала проверяется `pushManager.getSubscription()`, новая подписка создаётся только если её ещё нет.
- **Регистрация на коротком Android viewport не прокручивалась.** `PageTransition`, `body` и `#root` намеренно имеют `overflow:hidden`, поэтому сама страница регистрации обязана оставаться ограниченным scroll-контейнером `h-[100dvh] overflow-y-auto touch-pan-y` с momentum scrolling. `min-h-[100dvh]` растягивает её до высоты контента и оставляет без собственного scroll range, из-за чего кнопка и ссылка входа обрезаются родителем. Viewport использует `interactive-widget=resizes-content`, чтобы Chrome уменьшал видимую область при открытии клавиатуры. Не заменять `h` обратно на `min-h` и не лечить это глобальной прокруткой.
- **Незавершённая регистрация больше не блокирует email.** `users.email_verified_at` отделяет ожидающий аккаунт от подтверждённого. Повторный `POST /auth/register` для ожидающего аккаунта обновляет OTP и продолжает тот же аккаунт; только подтверждённый email получает `409` и кнопку входа. Подарок отправляется один раз непосредственно в `register()`, а не из `verifyOtp()`.
- **Вечный login-прелоадер был отдельной навигационной ошибкой.** OTP-вход больше не включает onboarding-loader до проверки профиля. Bootstrap профиля различает `готов`, `не заполнен` и `ошибка`; ошибка показывает явный повтор, а незаполненный аккаунт открывает `/profile-setup` без перекрывающей заставки.
- **OTP и welcome-письма обязаны быть mobile-fluid именно в Gmail.** Внешняя таблица — `width="100%"`, а внутренняя — гибридная `class="email-shell" width="520"` с `max-width:100%` и media-query, который на ширине до 520 px принудительно ставит `width:100%!important`. Это не позволяет Gmail Android вычислить широкую естественную ширину и обрезать письмо. Внутренние отступы рассчитаны на 320 px, а OTP отображается одним блоком. Нельзя возвращать четыре ячейки кода. По просьбе владельца в шапке возвращён классический фирменный знак `YoYoJoy Day 🌿` и зелёный цвет `#0E6E62`; внешние картинки для самого знака не требуются.
- **Android может выгрузить вкладку, пока пользователь открывает почту за OTP.** Контекст незавершённого OTP (`email`, регистрация/вход, статус подарка) хранится отдельно в `localStorage` с TTL 30 минут и очищается после успешной проверки. Нельзя снова полагаться только на Zustand `email` или `location.state`: они теряются при восстановлении вкладки и оставляют OTP-экран без адреса.
- **Onboarding-loader имеет жёсткую конечную ветку.** `/today` ограничен HTTP-таймаутом, а preload картинки настроения дополнительно завершается максимум через 4 секунды даже без `load/error`. Нельзя добавлять в путь прелоадера Promise без таймаута.
- **Старый мобильный Zustand-кэш нельзя доверять после обновлений.** Persisted state версионируется и перед гидратацией нормализует `bookmarks`, цели, праздники, заботу, offline queue и `dailyPack`. Иначе старая/частично записанная коллекция может уронить Home до первого запроса к API и показать глобальный экран «Что-то пошло не так».
- **Анимации лендинга работают всегда.** Глобальный `prefers-reduced-motion` override удалён по продуктовому решению: CTA пульсируют и элементы мокапа двигаются независимо от системной настройки.
- **Material Symbols превращались в `auto_awesome`/`favorite` на медленной сети.** Иконки больше не зависят от Google Fonts: используемый набор сокращён до локального WOFF2 (~23 КБ). До подтверждённой загрузки font-face класс `material-symbols-ready` не выставляется, поэтому сырой текст лигатур не показывается. Не возвращать внешний Google Fonts URL или полный шрифт на ~488 КБ.
- **Старт PWA защищён бюджетом производительности.** Landing грузится отдельно от auth/app-страниц и нижних секций, фотографии настроения ленивые, onboarding-лотос — WebP ~14 КБ и не загружается на лендинге. `npm run check:performance` ограничивает главный bundle (140 КБ gzip, включая исходный Motion-переход) и service-worker precache (650 КБ). PWA регистрируется только через `PWAUpdater`; повторную регистрацию в `main.tsx` не добавлять. Обновление применяется сразу на безопасных экранах и откладывается до ухода со страницы на формах, чтобы не стереть ввод. После первого рендера авторизованного shell только чанки Дом/Закладки/Настройки/Уведомления прогреваются в idle-время (и по `pointerdown` вкладки); auth, прелоадер и тяжёлые изображения заранее не загружаются.
- **`AnimatePresence mode="popLayout"`** для переключения списка/детальной карточки (праздники, дни заботы) даёт «призрачное» наложение старого и нового контента при разных по форме элементах — пробовали, увидели регресс на скриншоте, откатили обратно на простой keyed remount без exit-анимации.

API отдаёт картинку выбранного тона, UI не дублирует уже нанесённый текст, Web Share отправляет файл с fallback на публичную ссылку, закладки сохраняют снапшот изображения. `01-114` называется «Праздник дат и планов».
9. **AI и ввод имени** — код переведён на provider-neutral Workers AI-конфигурацию и `@cf/openai/gpt-oss-120b`; восстановлен короткий стиль контента, Redis-ключи версионированы как `short-v2`, старые длинные DailyFeed пересобираются, fallback не сохраняется в PostgreSQL. 10. **Восстановление push на новом устройстве** — Settings не загромождается статусом исправного устройства: при подтверждённой подписке блок скрыт. Если подписки нет, CTA «Подключить уведомления» по пользовательскому жесту создаёт и синхронизирует её; при запрете или неподдерживаемом браузере остаётся только правдивая инструкция. Никакой тестовый push после подключения не отправляется.
11. **PWA-handoff и вход на новом устройстве** — настройку профиля по-прежнему можно продолжить в обычном браузере. На iPhone после инструкции «Добавить на экран Домой» приложение дополнительно предупреждает, что push нужно подключать уже из установленной YoYoJoy; прямого автоматического перехода Safari → PWA нет. После каждого успешного OTP-входа frontend ставит одноразовый флаг в `sessionStorage` и в основном layout проверяет подписку именно текущего устройства через существующий `useWebPush`. Уже подключённое устройство проходит проверку бесшумно; неподключённое получает CTA разрешения, а «Настроить позже» скрывает окно только до следующего успешного входа. При `denied`, неподдерживаемом браузере или iPhone Safari показывается соответствующая инструкция без ложного системного запроса.
12. **Регистрация на Android** — при высоте viewport до 700px форма переходит в компактный режим: обязательные поля, согласие, CTA и вход помещаются на обычном экране `360×640`, а при открытой клавиатуре остаётся рабочая вертикальная прокрутка с `touch-pan-y`. Если backend отвечает `409`, рядом с ошибкой появляется явная кнопка «Войти в аккаунт»: она открывает login с уже заполненным, но редактируемым email и не отправляет второй OTP автоматически.
13. **Возврат плавности и PWA-регрессий** — переходы `Дом → Закладки → Настройки → Дом` и на отдельные экраны снова используют исходный `Framer Motion` (`x: 15 → 0`, `y: 10 → 0`) через лёгкий `LazyMotion/domAnimation`, при этом страницы и тяжёлый лоадер остаются ленивыми. Локальный Material Symbols WOFF2 ограничен манифестом `src/config/materialSymbols.ts`; при новой literal-иконке нужно добавить её в манифест и пересобрать WOFF2. Базовый размер иконок — `24px`. PWA-обновление не меняет серверные тумблеры push и не отправляет тестовый push.
14. **Плавный первый переход, адаптив и письма** — первый переход вкладок больше не ждёт загрузку чанка: после app-shell прогреваются только нужные экраны в idle-время, а `pointerdown` вкладки начинает импорт ещё до навигации. На мобильном экране фильтры Закладок — полная сетка (2 колонки, с 400 px — 3), без горизонтального swipe, распорок, градиентов и частично видимых кнопок. Формы и OTP имеют реальную ширину под 320 px: текст согласия переносится, элементы кода гибко сжимаются. Системные письма используют классический знак `YoYoJoy Day 🌿`, зелёную шапку `#0E6E62` и fluid-таблицы.
