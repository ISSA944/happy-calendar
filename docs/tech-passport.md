# YoYoJoy Day
## Полный технический паспорт продукта и архитектурная карта системы

---

## 1. Общее описание

YoYoJoy Day — это мобильное приложение, которое не нужно скачивать из App Store или Google Play. Оно открывается прямо в браузере телефона по ссылке, а при желании устанавливается на главный экран одним нажатием — и выглядит как обычное приложение с иконкой. Такой формат называется PWA (Progressive Web App).

Попасть в приложение просто: пользователь сканирует QR-код на физическом календаре — и сразу оказывается внутри. Никаких лишних шагов.

**Главная идея:** в основе приложения — искусственный интеллект. Именно AI каждый день создаёт персональный гороскоп, подбирает фразу поддержки под настроение пользователя и готовит праздник дня. Контент всегда уникальный и живой — не шаблоны, а текст, сгенерированный специально под конкретного человека с учётом его знака зодиака и текущего настроения.

Каждый день — новый контент. Система кэширует уже готовые ответы AI и переиспользует их для пользователей с одинаковыми параметрами, что позволяет экономить ресурсы и обеспечивать мгновенную скорость загрузки.

## 2. Визуальный путь пользователя (Screen-by-Screen Flow)

---

### 2.1 QR-код

Точка входа в приложение — QR-код, размещённый на физическом бумажном календаре YoYoJoy. Пользователь наводит камеру телефона на код — и браузер автоматически открывает сайт, который можно добавить на главный экран телефона. Никаких поисков в интернете, никаких магазинов приложений. Один скан — и человек уже внутри.

---

### 2.2 Экран приветствия (Welcome)

Первый экран, который видит пользователь. Встречает его спокойно и без лишнего шума — тёплые фирменные тона, плавные анимации и простой посыл: здесь можно выдохнуть. Экран полностью реализован по макету дизайн-системы YoYoJoy: цвета, шрифты, скругления — всё соответствует бренду.

На экране три иконки с ключевыми функциями приложения, анимированный орб в центре и единственная кнопка — «Начать», которая ведёт к регистрации.

Поддерживается горизонтальный режим: при повороте телефона контент автоматически перестраивается — текст и иконки слева, орб справа. Всё выглядит аккуратно в любом положении телефона.

---

### 2.3 Экран регистрации и вход в аккаунт

**Регистрация**

Простая форма без паролей. Пользователь заполняет два поля: имя (необязательно — если оставить пустым, приложение просто не будет обращаться по имени) и электронная почта (обязательно — на неё придёт код для входа). Далее нужно поставить галочку согласия на обработку персональных данных — без этого кнопка «Получить код» остаётся неактивной. Рядом — ссылка на полный текст Политики конфиденциальности, которую можно прочитать не покидая страницу. Отдельно можно подписаться на рассылку — по желанию.

Если пользователь вводит email, который уже зарегистрирован — появляется ошибка «Этот email уже зарегистрирован» и предложение войти в аккаунт. Это исключает путаницу и дублирование аккаунтов.

Внизу страницы — ссылка «Уже есть аккаунт? Войти» для тех, кто уже регистрировался.

Горизонтальный режим поддерживается: форма и описание располагаются в двух колонках.

**Техническая часть — Регистрация:**

При регистрации система первым делом проверяет — есть ли уже такой email в базе данных. Если есть — создание нового аккаунта блокируется, появляется ошибка. Если email новый — создаётся аккаунт, генерируется случайный 4-значный код и отправляется на почту. Этот код нигде не хранится в открытом виде — только в зашифрованной форме, которую невозможно прочитать даже при полном доступе к базе данных. Код живёт 15 минут, после чего автоматически удаляется. Когда пользователь вводит правильный код — система его проверяет, сразу удаляет из базы (чтобы нельзя было использовать повторно) и выдаёт два ключа доступа: короткий (действует 15 минут) и длинный (действует 30 дней). Короткий используется для всех действий в приложении, длинный — для автоматического обновления сессии в фоне. Пользователь этого не замечает.

---

**Вход в аккаунт**

Отдельный экран для пользователей, которые уже регистрировались. Встречает заголовком «С возвращением». Пользователь вводит email — получает код — входит. Никакого пароля запоминать не нужно. Если email не найден — понятная ошибка. Внизу — ссылка «Ещё нет аккаунта? Зарегистрироваться».

Горизонтальный режим поддерживается.

**Техническая часть — Вход в аккаунт:**

При входе система проверяет существование email в базе — если не найден, возвращает ошибку. Если найден — генерируется новый код и отправляется на почту. Каждый новый запрос кода автоматически делает предыдущий недействительным — нельзя накопить несколько кодов и использовать старый. После 5 неверных попыток ввода кода система блокирует вход на 1 час — защита от автоматических атак. После успешного входа пользователь сразу попадает на главный экран с прелоадером.

### 2.4 OTP — проверка почты и Политика конфиденциальности

**Экран проверки почты (OTP)**

После ввода email пользователь видит экран с четырьмя полями для ввода кода. Письмо с кодом приходит на почту в течение нескольких секунд. Пользователь вводит 4 цифры и нажимает «Продолжить». Если код не пришёл — через 30 секунд появляется кнопка «Отправить код ещё раз». При входе в аккаунт заголовок экрана меняется на «Вход в аккаунт» — чтобы пользователь понимал в каком режиме находится.

**Техническая часть:**

Код генерируется случайным образом на сервере — приложение в браузере его никогда не видит. Это исключает возможность перехвата до отправки. Код немедленно шифруется алгоритмом bcrypt (стандарт безопасного хранения данных) и сохраняется в базе данных уже в зашифрованном виде — даже при утечке базы коды бесполезны. При вводе кода система сравнивает зашифрованные значения — оригинальный код при этом нигде не фигурирует. После успешной проверки код сразу удаляется. Повторно использовать невозможно. Защита от перебора: 5 неверных попыток — блокировка на 1 час. Повторный запрос кода автоматически обнуляет предыдущий. OTP рассылается с помощью сервиса gmail SMTP. Я хочу подключить Resend для рассылки писем, но пока что нужно добавить DNS новые в reg.ru.

**Политика конфиденциальности**

Отдельный экран с полным текстом политики. Открывается по ссылке прямо со страницы регистрации — пользователь читает и возвращается обратно без потери данных формы. Текст политики актуален и соответствует требованиям законодательства о персональных данных.Но сейчас там стоит просто заглушка, пришлите текст или дайте фидбек по поводу данного блока.

### 2.5 Разрешение на уведомления и (Инструкция для iOS)

**Разрешение на уведомления**

После успешной регистрации приложение запрашивает разрешение на push-уведомления. Без этого разрешения утренние напоминания работать не будут — система не сможет отправлять сообщения на заблокированное устройство. Время отправки пользователь настраивает сам в разделе настроек.

Уведомления отправляются через стандартный браузерный Web Push — это технология, которая работает без сторонних сервисов прямо через браузер телефона. На Android уведомления работают в любом браузере. На iPhone — только  если приложение добавлено на главный экран.

**Техническая часть уведомлений:**

Сервер запускает фоновую задачу каждую минуту. Для каждого пользователя она вычисляет локальное время в сохранённом IANA-часовом поясе и сравнивает его с отдельным расписанием каждой категории. Отправка запускается, если у пользователя есть активная подписка, соответствующая категория включена и её время совпало с точностью до минуты.

Если все условия выполнены — сервер получает персональный контент пользователя на сегодня и отправляет уведомление на каждое его устройство отдельно. Один аккаунт — несколько телефонов — уведомление приходит на все одновременно.

Каждое успешно отправленное уведомление записывается в базу данных с датой, типом и текстом. Именно поэтому в разделе «Уведомления» хранится полная история — она формируется на сервере, а не в браузере, и доступна с любого устройства.

---

**Инструкция для iOS (только для iPhone)**

На iPhone Safari для того чтобы предупредить пользователя о том, что уведомления будут работать только после добавления приложения на главный экран, реализован отдельный экран с пошаговой инструкцией:
1. Нажать кнопку «Поделиться» в Safari (квадрат со стрелкой вверх)
2. Выбрать «На экран Домой»
3. Нажать «Добавить»

После этого приложение появляется на рабочем столе с иконкой YoYoJoy и открывается без адресной строки браузера — как настоящее нативное приложение. Только после установки на главный экран на iPhone начнут приходить push-уведомления.

На Android этот экран не показывается — там браузер сам предлагает установку.

Горизонтальный режим поддерживается на обоих экранах.

### 2.6 Настройка профиля (дата рождения, знак зодиака, пол)

Все данные профиля хранятся в базе данных PostgreSQL и привязаны к аккаунту, а не к устройству. При входе с любого телефона или браузера — имя, знак зодиака, пол, аватарка и все настройки загружаются с сервера и восстанавливаются автоматически.

Дата рождения и знак зодиака. Дата отправляется на сервер в формате ДД.ММ.ГГГГ. Сервер автоматически вычисляет знак зодиака по стандартным астрологическим диапазонам и сохраняет оба значения одновременно. Знак зодиака используется как ключ при каждом обращении к AI — именно по нему генерируется гороскоп и подбирается стиль фразы поддержки.

Пол. Сохраняется в базе и передаётся AI при каждой генерации. Благодаря этому все тексты автоматически согласованы по роду: «устал» или «устала», «вдохновлён» или «вдохновлена».

Аватарка. Выбранное фото сжимается прямо в браузере до 512×512 пикселей и конвертируется в формат JPEG с качеством 92%. Итоговый файл сохраняется в базе данных. Максимальный размер — 2 МБ. При входе с другого устройства аватарка загружается с сервера и отображается мгновенно.

Время уведомлений (Push-уведомления)

Пользователь отдельно выбирает время для гороскопа, поддержки, календарных праздников и персональной заботы. Каждую категорию можно включить или отключить независимо. Если несколько категорий назначены на одну минуту, они приходят отдельными уведомлениями.

На iPhone уведомления работают только если приложение добавлено на главный экран — это ограничение Apple, не приложения. На Android работает в Chrome без дополнительных условий. Яндекс Браузер и другие сторонние браузеры на Android push-уведомления не поддерживают.

Техническая часть — Push-уведомления:

Система построена на технологии Web Push API с VAPID-аутентификацией — без Firebase, без сторонних SDK, без зависимости от Google-сервисов в коде приложения. Всё работает на уровне браузера и сервера напрямую.

Подписка на уведомления. После разрешения уведомлений приложение с действующей сессией получает VAPID-публичный ключ запросом `GET /api/push/public-key`, а затем передаёт его в `PushManager.subscribe()`. Ключ выдаёт работающий backend: он не зашит в JavaScript-сборку и не зависит от переменной `VITE_WEB_PUSH_PUBLIC_KEY`, поэтому замена ключа на сервере не требует пересборки фронтенда. В ответ браузер возвращает объект подписки — три строки: endpoint (уникальный адрес доставки), p256dh и auth (криптографические ключи для шифрования). Этот объект отправляется на сервер и сохраняется в таблице web_push_subscriptions. Один пользователь может иметь неограниченное количество подписок — по одной на каждое устройство и браузер. При повторной подписке с того же браузера запись обновляется (upsert по endpoint), дубликатов не создаётся.

Отправка. Сервер каждую минуту запускает фоновую задачу (CRON), вычисляет текущее `HH:mm` в часовом поясе пользователя и сравнивает его с отдельными полями времени четырёх категорий. Каждый календарный праздник отправляется отдельно. Персональная забота отправляется отдельно по каждой активной и ещё не выполненной сегодня цели; если активных целей нет, push этой категории не создаётся. Веха прогресса также приходит отдельным push с названием цели. Каждый сформированный push отправляется на все активные устройства пользователя. Для доставки используется библиотека web-push с VAPID и шифрованием payload ключами конкретной подписки.

Мёртвые подписки. Если браузер вернул статус 410 или 404 при попытке доставки — подписка считается недействительной (пользователь отозвал разрешение или переустановил браузер) и автоматически удаляется из базы.

История уведомлений. Каждое успешно отправленное уведомление записывается в таблицу notifications с датой, типом и текстом. Именно эти записи отображаются в разделе «Уведомления» в приложении — история формируется на сервере, не в браузере

Время уведомлений и часовой пояс. Пользователь выбирает обычное локальное время — например, 09:00 по Москве. Браузер передаёт `09:00` без конвертации, сервер хранит его как локальное `HH:mm` и при каждом запуске cron сравнивает с текущим временем в `prefs.timezone`. Это исключает двойную UTC-конвертацию. Горизонтальный режим поддерживается.

### 2.7 Главный экран (Home) и История уведомлений

**Главный экран**

Центральный экран приложения. Каждый день — новый уникальный контент от AI.

**Блок настроения** — пользователь выбирает одно из шести состояний: Нормально, Вдохновлён(а), Спокоен(йна), Тревожусь, Грустно, Устал(а). При смене настроения обновляется только блок поддержки — гороскоп и праздник остаются прежними. Это сделано намеренно: нет смысла пересчитывать гороскоп из-за изменения настроения, а AI-вызов — это ресурс, который нужно использовать разумно. Каждому настроению соответствует своя иллюстрация.

**Блок гороскопа** — персональный текст по знаку зодиака, каждый день новый. Генерируется AI с учётом знака и текущей даты. Можно сохранить в закладки.

**Блок поддержки** — тёплая фраза под текущее настроение. Тоже генерируется AI. Кнопка «Другая фраза» позволяет обновить текст до 5 раз в день — больше не нужно, чтобы не превращать поддержку в бесконечный перебор. Можно сохранить в закладки.

**Блок праздника дня** — интересный праздник с поздравлением. Меняется каждый день. Можно сохранить в закладки.

**Как работает AI на главном экране:**

Когда пользователь открывает приложение, система проверяет — есть ли уже готовый контент на сегодня для этого знака зодиака и настроения. Если есть — отдаёт мгновенно из быстрого хранилища (Redis). Если нет — обращается к AI, получает ответ, сохраняет его и отдаёт пользователю. Следующий пользователь с тем же знаком и настроением уже получит готовый результат без нового вызова AI. Это называется кэширование — умное переиспользование уже готовых ответов.

Горизонтальный режим поддерживается: блоки перестраиваются в сетку.

---

**История уведомлений**

Раздел, куда попадают все push-уведомления, которые когда-либо приходили пользователю. Каждое уведомление отображается с датой (Сегодня, Вчера, 12 мая и т.д.) и типом — гороскоп, поддержка или праздник.

В горизонтальном режиме — фото настроения слева, карточки уведомлений справа.

### 2.8 Закладки и Настройки

**Закладки**

Пользователь может сохранять понравившиеся тексты — гороскоп или фразу поддержки. Важный момент: текст сохраняется как снимок на момент нажатия. Даже если завтра AI сгенерирует другой гороскоп — сохранённая закладка останется прежней навсегда. Это сделано специально: человек сохраняет то, что его тронуло именно сегодня, и это не должно меняться.

Список всех закладок отображается с датой сохранения. Любую закладку можно удалить.

Горизонтальный режим поддерживается.

---

**Настройки**

Раздел управления аккаунтом и предпочтениями. Все функции:

- **Имя и email** — отображаются данные текущего аккаунта
- **Смена email** — пользователь может изменить адрес почты. Процесс: ввести новый email → получить код подтверждения → ввести код → email изменён. Старый адрес при этом перестаёт работать
- **Время уведомлений** — в какое время присылать ежедневный контент
- **Контент уведомлений** — пользователь может выбрать, какие уведомления он хочет получать — гороскоп, поддержку или праздник.
- **ВЫХОД ИЗ АККАУНТА**- сейчас реализован для тестировки в скорем времени уберу.

Горизонтальный режим поддерживается.

## 3. Технический стек — что использовано и почему

---

**Приложение в браузере (Frontend)**

Написано на React 19 и TypeScript. React — это технология которая позволяет строить быстрые и отзывчивые интерфейсы. TypeScript добавляет строгую проверку кода ещё до запуска — это значит меньше ошибок в готовом продукте. Для стилей используется Tailwind CSS — он позволяет быстро и точно реализовывать любой дизайн, включая горизонтальный режим для всех экранов. Анимации сделаны на Framer Motion — библиотека, которая обеспечивает плавные, естественные переходы между экранами. Состояние приложения (данные пользователя, контент дня) хранится в Zustand — лёгкое и надёжное хранилище, которое работает даже без интернета.

---

**Сервер (Backend)**

Написан на Node.js и NestJS. Node.js — это быстрая серверная платформа, NestJS — структурированный фреймворк поверх неё. Вместе они обеспечивают надёжную и масштабируемую работу API. Для работы с базой данных используется Prisma — инструмент, который гарантирует безопасные и типизированные запросы к базе.

---

**База данных**

PostgreSQL 15 — одна из самых надёжных реляционных баз данных в мире. Здесь хранятся все данные: аккаунты пользователей, профили, закладки, история уведомлений, сгенерированный AI контент.

---

**Быстрое хранилище (Redis)**

Redis — это сверхбыстрое хранилище в оперативной памяти сервера. У каждого пользователя дневной AI-пакет кэшируется по версии, знаку, настроению и ISO-дате на 36 часов; имя в ключ и логи не попадает. Пять коротких фраз поддержки хранятся отдельным пулом 24 часа, поэтому кнопка «Другая фраза» обычно не вызывает AI. Fallback живёт только 300 секунд.

---

**Искусственный интеллект**

Используется модель `@cf/openai/gpt-oss-120b` через Cloudflare Workers AI. Сервер проверяет каждый JSON-ответ через Zod: «Главное» занимает 2–4 предложения, «Подробнее» 3–4, поддержка 1–2. Повреждённый или слишком длинный ответ повторяется один раз. При недоступности AI короткий fallback хранится только 5 минут в Redis и не становится постоянным дневным прогнозом в PostgreSQL. Новый профиль начинает с настроения `Нормально`. AI-токен хранится только в production `.env` — приложение в браузере его никогда не видит.

---

**Отправка писем (OTP)**

Для отправки одноразовых кодов на email используется SMTP через Gmail. В процессе подключения также Resend — современный сервис для надёжной доставки писем. Письма отправляются от имени YoYoJoy Day с фирменным оформлением.

---

**Push-уведомления**

Реализованы через стандартный Web Push API — без Firebase и без зависимости от Google. VAPID-пара хранится только в окружении backend (`WEB_PUSH_PUBLIC_KEY`, `WEB_PUSH_PRIVATE_KEY`, при необходимости `WEB_PUSH_SUBJECT`); приватный ключ никогда не отдаётся клиенту. При подписке авторизованный frontend получает публичный ключ через `GET /api/push/public-key`, поэтому в production frontend не нужны VAPID- или Firebase-переменные. Сервер хранит токены подписки каждого пользователя и каждую минуту проверяет расписание. Уведомления приходят точно в выбранное пользователем время с учётом его часового пояса.

---

**Сервер и хостинг**

Всё работает на VPS-сервере в России (Timeweb Cloud) в Docker-контейнерах. Docker — это технология изоляции, которая позволяет запускать несколько независимых сервисов на одном сервере: API, база данных, Redis, Nginx. Nginx — это веб-сервер, который принимает все входящие запросы и направляет их куда нужно. SSL-сертификат (шифрование соединения) выдан Let's Encrypt, действует до августа 2026, автоматически обновляется.

---

## 4. Безопасность

- Паролей не существует — только одноразовые коды. Красть нечего
- Все коды хранятся в зашифрованном виде (bcrypt) — даже при утечке базы данных они бесполезны
- JWT-токены с автообновлением — пользователь не замечает смены токена, сессия защищена
- Rate limiting — автоматическая блокировка при подозрительной активности
- HTTPS — весь трафик зашифрован
- AI-ключи только на сервере — никогда не передаются в браузер
