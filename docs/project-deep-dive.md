# YoYoJoy Day — технический обзор

> За актуальными статусом production, открытыми хвостами и процедурами деплоя обращаться к [`PROJECT_MEMORY.md`](../PROJECT_MEMORY.md). Этот файл описывает устройство системы, а не оперативное состояние.

## Что это такое?

YoYoJoy Day — это PWA-приложение (Progressive Web App), компаньон к бумажному ежедневнику.
Пользователь сканирует QR-код на бумажном календаре, проходит регистрацию и каждый день 
получает персонализированный контент: гороскоп, фразу поддержки и праздник дня.

Продакшн: https://yoyojoy.online (фронт + бэк на Timeweb VPS 157.22.198.107)

## Пользовательский путь (User Flow)

### Онбординг (один раз):
```
1. QR-код → WelcomePage
2. Нажимает "Начать" → RegistrationPage
3. Вводит email → POST /api/auth/register → OTP и отдельное письмо с двумя PDF на почту
4. Вводит OTP → POST /api/auth/verify-otp → получает JWT токены
5. Страница NotificationsPage → запрос на push-уведомления
6. ProfileSetupPage → вводит дату рождения, пол, имя
7. Прелоадер 6 секунд (анимация) → HomePage
```

### Ежедневный цикл:
```
1. Push-уведомление в выбранное время
2. Нажимает → открывается https://yoyojoy.online/home
3. Видит гороскоп, фразу поддержки, праздник дня
4. Может сохранить в закладки (JSONB снапшот момента)
5. Может сменить настроение → обновляется ТОЛЬКО фраза поддержки
```

## Глобальный стейт (Zustand Store)

Файл: `src/store/app.store.ts`

Весь стейт приложения живёт в одном store `useAppStore`. Он персистируется в localStorage 
(ключ `yoyojoy-store`). При перезагрузке — восстанавливается.

Важные части стейта:
- `currentMood` — текущее настроение пользователя
- `dailyPack` — объект с гороскопом, фразой, праздником (приходит с бэка)
- `bookmarks` — список сохранённых карточек
- `offlineQueue` — очередь задач при потере сети (закладки)
- `hasCompletedOnboarding` — флаг завершения онбординга

Ключевые методы:
- `initDailyPack()` — загружает сегодняшний контент с бэка
- `setMood(mood)` — меняет настроение + получает новую фразу с бэка
- `refreshSupportPhrase()` — "Другая фраза" (POST /api/today/support/next)
- `addBookmark()` / `removeBookmark()` — работа с закладками (optimistic update)
- `syncProfile()` — синхронизирует профиль с сервером при открытии

## Аутентификация (Auth Flow)

Используется passwordless (без пароля) — только OTP по email.

### JWT токены:
- **Access token** — короткий (15 минут), для каждого API запроса
- **Refresh token** — длинный (365 дней для тест-аккаунта), для получения нового access

Хранятся в localStorage через `src/auth/token-storage.ts`.

Axios interceptor автоматически:
1. Добавляет `Authorization: Bearer <token>` к каждому запросу
2. При 401 ошибке — пробует обновить через refresh token
3. Если refresh тоже не работает — разлогинивает

### OTP:
- 4 цифры, живёт 15 минут
- Хэшируется bcrypt перед сохранением в БД
- Два явно перечисленных тест-аккаунта имеют фиксированный OTP `1111` во всех окружениях, включая production: `mukaniskander01@gmail.com` сохраняет bypass без OTP-письма, а `metrolabsgroup@gmail.com` получает реальное письмо с кодом. Подарочные PDF отправляются только при первой регистрации нового email и не повторяются при входе. Это осознанный бэкдор, жёстко ограниченный точными адресами в `backend/src/auth/auth.service.ts`.
- Rate limiting: 10 попыток за 15 минут

## AI Логика (самое интересное)

### Что генерирует AI:
- `horoscope` — 2–4 предложения, 160–500 символов
- `horoscopeDetailed` — 3–4 предложения, 350–850 символов
- `advice` — 1–2 практических предложения, 60–220 символов
- `moon` / `aspect` — ровно по одному предложению, 45–180 символов
- `supportPhrase` — 1–2 предложения, 60–220 символов

**Праздник** НЕ генерируется AI — берётся из локального словаря `holidays.data.ts`.

### Модель:
`@cf/openai/gpt-oss-120b` через OpenAI-compatible endpoint; JSON дополнительно проверяется Zod.

### Кэширование (3 уровня):
```
1. DB Cache  — DailyFeed таблица (userId + date)
              Если уже есть запись на сегодня → возвращаем её.

2. Redis Cache — персональный ключ: pack:short-v2:{userId}:{zodiacSign}:{mood}:{YYYY-MM-DD}
              TTL: 36 часов (покрывает все часовые пояса РФ).
              Если fallback-ответ → TTL 5 минут и meta.contentSource=fallback.

3. Distributed Lock — предотвращает двойной вызов AI
              Если запрос уже идёт → ждём 1 сек и проверяем Redis снова.
```

### Fallback (Mock Mode):
Если Workers AI недоступен или ключ не задан — бэкенд НЕ падает.
Возвращает данные из встроенных словарей:
- 12 готовых гороскопов (по одному на каждый знак)
- 5 фраз поддержки для каждого из 6 настроений

Fallback не записывается в `horoscopes`, `support_phrases` или `daily_feed`: он живёт в Redis 300 секунд, после чего фронт тихо повторяет `/api/today`. Старый сохранённый feed, нарушающий короткий контракт, автоматически пересобирается. Живой JSON принимается только после Zod-проверки объёма и структуры. Прямой OpenAI с московского VPS не используется, потому что отвечает `403 unsupported_country_region_territory`; актуальный провайдер — Cloudflare Workers AI, модель `@cf/openai/gpt-oss-120b`.

## Механика смены настроения (Hybrid Flow)

Это ключевая экономия токенов:

```
Пользователь меняет настроение
         ↓
PATCH /api/profile/mood  
         ↓
Бэкенд вызывает updateMoodSupport() в AiService
         ↓
AI генерирует ТОЛЬКО новую фразу поддержки
(гороскоп не трогается — он дорогой)
         ↓
Фраза возвращается на фронт
         ↓
Zustand обновляет ТОЛЬКО supportPhrase в dailyPack
(остальное остаётся)
```

Почему так: полный пакет стоит ~500-800 токенов. Одна фраза — ~50 токенов.

## Push-уведомления

### Как работают:
1. Фронт запрашивает разрешение → браузер даёт subscription объект
2. Subscription (endpoint + ключи) сохраняется в БД
3. CRON-задача каждую минуту получает локальное время пользователя в его IANA timezone
4. Сверяет отдельные расписания гороскопа, поддержки, праздников и персональной заботы
5. Отправляет через web-push (протокол Web Push API)

### CRON (каждую минуту):
```
Для каждого пользователя получает текущее время в его IANA timezone (HH:mm)
Сравнивает его с локальным временем, выбранным для каждой включённой категории
Для каждой сработавшей категории собирает отдельные push → отправляет на все устройства
→ логирует каждый успешно отправленный логический push в notifications
```

Праздники не сворачиваются в счётчик: каждый приходит отдельно. Персональная забота также
приходит отдельным push для каждой активной цели, кроме уже выполненных сегодня; UI-fallback
`calm` при отсутствии целей в cron не используется. Вехи отправляются отдельно по каждой цели
и явно называют её в тексте.

### Особенность фраз в push:
Для уведомлений берётся НЕ сегодняшняя фраза, а новая из Redis-пула.
Пул заполняется 5 фразами за один AI-вызов. Каждый push "вытаскивает" одну.
Когда пул пустой — AI генерирует новый батч из 5 фраз.

## Роутинг и Guards

В `App.tsx` определены 3 типа защиты:

```
RootGuard         — для '/' маршрута
  Нет токена → WelcomePage
  Есть токен + нет онбординга → profile-setup
  Всё ок → /home

RequireAuth       — только проверяет наличие токена
  Нет токена → '/'

RequireAppReady   — проверяет токен + завершённость онбординга
  Нет токена → '/'
  Нет онбординга → profile-setup
  Всё ок → рендерит детей
```

Главные страницы (/home, /bookmarks, /settings, /notifications-list) 
живут внутри `AppLayout` с единым ключом `'app-shell'` — это значит 
при переходе между вкладками AppLayout НЕ перемонтируется (производительность).

## База данных (PostgreSQL + Prisma)

Основные таблицы:
```
users              — email, name, OTP хэш/expires
profiles           — дата рождения, знак зодиака, пол, настроение
prefs              — часовой пояс, отдельные времена и флаги четырёх категорий push
horoscopes         — гороскопы (date + zodiacSign как уникальный ключ)
support_phrases    — фразы поддержки (per-user)
holidays           — праздники дня (date как уникальный ключ)
daily_feeds        — связка: userId + date → horoscope + supportPhrase + holiday
bookmarks          — закладки (JSONB payload = снапшот текста на момент сохранения)
web_push_subscriptions — endpoint + ключи для Web Push
notifications      — история отправленных push-уведомлений
```

Важно: все таблицы в snake_case. Никогда не писать PascalCase в SQL.

## Критичные правила (нарушать нельзя)

1. **AI только на бэке** — фронт никогда не знает об AI ключах
2. **При смене настроения** — меняется ТОЛЬКО фраза поддержки, гороскоп неизменен
3. **Закладки — снапшот** — текст фиксируется в момент сохранения, не обновляется
4. **Landscape только через** `landscape:` Tailwind модификатор
5. **Push расписание — только сервер** — фронт только даёт FCM/WebPush токен
6. **Fallback обязателен** — бэк никогда не должен падать из-за OpenAI
