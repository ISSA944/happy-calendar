# Возврат короткого AI-контента и нормального начального настроения

Дата: 2026-08-10

## Цель

Вернуть удачный стиль AI-контента из версии `c36f7ed`: короткие тёплые фразы поддержки и компактные гороскопы, которые быстро генерируются и не расходуют лишние токены. При этом сохранить появившиеся позже гарантии: Cloudflare Workers AI, Zod-валидацию, один повтор повреждённого JSON, ISO-даты, Redis, PostgreSQL и запрет постоянного сохранения fallback.

## Контракт текстов

Все ограничения проверяются сервером после очистки HTML и нормализации пробелов.

| Поле | Предложения | Символы | Содержание |
| --- | ---: | ---: | --- |
| `horoscope` («Главное») | 2–4 | 160–500 | Конкретный прогноз для знака на текущую дату, без перечисления всех планет |
| `horoscopeDetailed` («Подробнее») | 3–4 | 350–850 | Умеренно подробный разбор с планетой-покровителем и лунной энергией |
| `advice` | 1–2 | 60–220 | Один конкретный применимый шаг |
| `moon` | 1 | 45–180 | Фаза Луны и влияние на знак |
| `aspect` | 1 | 45–180 | Один главный аспект дня |
| `supportPhrase` | 1–2 | 60–220 | Тёплая поддержка под настроение, без длинной психологической лекции |

Промпты возвращаются к формулировкам рабочей версии: живой русский язык, принятие состояния без осуждения, конкретность, отсутствие клише и тон близкого человека. Минимальные границы защищают от пустых односложных ответов; максимальные — от простыней текста.

## AI и лимиты

- Провайдер и модель не меняются: Cloudflare Workers AI, `@cf/openai/gpt-oss-120b`, `reasoning_effort: low`.
- Стартовые бюджеты: дневной пакет — `1400`, одиночная поддержка — `400`, пакет поддержек — `1200` `max_completion_tokens`.
- Перед production-деплоем бюджеты проверяются синтетическими русскими запросами. Их можно только уменьшить либо, при доказанном обрезании валидного JSON, увеличить до минимального проходящего значения.
- Невалидный JSON или текст вне контракта повторяется ровно один раз. Политика HTTP-retry остаётся прежней.
- Fallback тоже соответствует короткому контракту.

## Redis и PostgreSQL

- Дневной AI-пакет остаётся в Redis на 36 часов; fallback — только на 300 секунд.
- Пул кнопки «Другая фраза» содержит пять коротких поддержек и живёт в Redis 24 часа. Первая фраза возвращается сразу, остальные используются без нового AI-запроса; фоновое пополнение сохраняется.
- Redis-ключи получают версию `short-v2`, поэтому старые длинные значения не участвуют в выдаче.
- Для одного пользователя, знака, настроения и ISO-даты повторная загрузка использует PostgreSQL или Redis и не вызывает AI.
- Старый `DailyFeed` считается устаревшим, если любой его AI-текст нарушает новый контракт. Такой feed пересобирается; `Horoscope` обновляется новыми полями при upsert, а поддержка заменяется новой записью. Закладки не меняются, потому что хранят JSONB-снапшот.
- Успешный AI-контент сохраняется в PostgreSQL. Fallback, как и сейчас, не создаёт `Horoscope`, `SupportPhrase` или `DailyFeed`.

## Начальное настроение

- Новый аккаунт и профиль без завершённого онбординга всегда начинают с `Нормально` на frontend и backend.
- Значение сбрасывается при переходе в новый онбординг, чтобы persisted-состояние предыдущего аккаунта не протекало в новый профиль.
- Обычный повторный вход существующего пользователя не сбрасывает его сохранённое настроение.
- Защищённые тестовые аккаунты Ольги и владельца сохраняют пользовательские данные при повторной регистрации; их существующее настроение меняется только самим пользователем, поскольку это уже не новый профиль.

## Производительность прелоадера

В этой задаче прелоадер не отвязывается от `/today`: сокращение промптов и токенов должно уменьшить время первого ответа. Отдельное изменение минимальных шести секунд и фоновой загрузки главного экрана не смешивается с восстановлением контента и может быть выполнено независимо, если после production-замеров задержка останется заметной.

## Тестирование

- Zod принимает тексты ровно в указанных диапазонах и отклоняет третье предложение поддержки, слишком длинное «Главное» и старый подробный текст.
- Промпты и `max_completion_tokens` проверяются тестами AI-сервиса.
- Повреждённый либо длинный ответ вызывает ровно один повтор; валидный короткий ответ принимается сразу.
- Все fallback-тексты проходят тот же контракт.
- Redis использует ключи `short-v2`, TTL 36 часов для pack, 24 часа для пула и 300 секунд для fallback.
- Повторная выдача того же дневного контекста не вызывает AI.
- Пять поддержек генерируются один раз и затем выдаются из Redis.
- Старый длинный `DailyFeed` пересобирается, а закладки остаются неизменными.
- Новый профиль получает `Нормально`; существующий профиль сохраняет выбранное настроение.
- После изменений проходят frontend/backend build, lint, Jest, Vitest и общий `npm run check`.

## Деплой и проверка

После обычного commit/push без force-push создаются резервные копии production `.env.prod` и PostgreSQL. Разворачиваются backend и frontend, затем техническим аккаунтом владельца проверяются Redis HIT, длины всех текстов, скорость первого `/today`, кнопка «Другая фраза» и отсутствие новых fallback-строк в PostgreSQL. За Ольгу вход не выполняется.
